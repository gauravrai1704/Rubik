# Short Solutions for Large Rubik's Cubes and Squares

One open engine for the **N×N×N Rubik's Cube** and the **N×N×1 Rubik's Square** at every size, with eight solvers and three
external baselines run on the same instances. Every solution is re-applied and verified by the engine, and every number in the
paper is generated by script from the result files in this repository.

**Authors:** Gaurav Rai, Kashvi Tak, Sharanya Gupta, Shaurya Sharma, Shree Gattani, Sunaina Goel.

## Main results

**Santa 2023 cubes** (Kaggle competition puzzles; mean quarter turns, the competition's score; lower is better).
Our main method, **SymPort**, runs KMCoders' own program on up to 48 rotated and mirrored copies of each puzzle and keeps the
shortest answer. It is shorter on average than KMCoders' published best-of-many solutions at every size from N = 4 to 7 and
second to them at N = 8 and 9, where we stopped.

| N | puzzles | **SymPort (ours)** | KMCoders published | KMCoders' program, one run | dwalton76 | KMC-Repro | NetGain | Demaine | Reduction | W/T/L vs published |
|---|---|---|---|---|---|---|---|---|---|---|
| 4 | 43 | **64.1** | 66.7 | 77.0 | 88.6 | 109.4 | 217.5 | 229.3 | 266.9 | 24/9/10 |
| 5 | 19 | **95.0** | 97.1 | 114.2 | 160.2 | 159.3 | 282.5 | 296.3 | 361.1 | 11/3/5 |
| 6 | 6 | **158.3** | 161.0 | 179.3 | 324.0 | 276.0 | 503.0 | 534.7 | 696.3 | 4/2/0 |
| 7 | 4 | **205.2** | 208.8 | 232.8 | 539.0 | 356.2 | 593.8 | 680.8 | 880.2 | 2/0/2 |
| 8 | 3 | 294.7 | **291.3** | 310.7 | 923.3 | 468.7 | 856.0 | 993.3 | 1,297.3 | 1/0/2 |
| 9 | 3 | 361.3 | **354.7** | 390.0 | 1,311.3 | 572.7 | 1,020.0 | 1,188.0 | 1,594.0 | 1/0/2 |
| all | 78 | **8,302** (total) | 8,452 | | | | | | | 43/14/21 |

Over all 78 puzzles SymPort is shorter on 43 and longer on 21 (two-sided sign test, p = 0.008; N = 4–7 alone: 41/14/17,
p = 0.002). Its gain shrinks with N because the copies' lengths spread by only about seven quarter turns at every size while
solutions grow as N² (paper, §7.3).

**Random cubes.** NetGain, our net-gain schedule for Demaine-style bulk commutators, is significantly shorter than our
3-cycle-batching adaptation of Demaine's algorithm from N = 5 on: 17% at N = 10 over 20 states (paired 95% intervals), and 26%
on the random 20×20×20 (4,925 against 6,612 HTM).

**Random Squares** (mean HTM). SymPort is the best method or tied for best at all 18 sizes N = 3–20: tied with the per-size
CayleyPy networks (one of its inner solvers) and with the exact optimum where it is known (N ≤ 5), and strictly shortest from
N = 9, where no per-size network exists. Exact God's numbers of the Square (colour goal): 6, 10 and 12 moves for N = 3, 4 and 5.

**How far from optimal.** A counting lower bound puts KMCoders' published Santa solutions at 1.81× the bound at N = 4 and
2.22× at N = 10.

## The methods

The paper uses names, the code uses numbers. Each solver package has its own `README.md`.

| Paper name | Code (registry name) | What it is | Kind | Owner |
|---|---|---|---|---|
| IDA\*-PDB | `m1_idastar` | Korf's IDA\* with pattern databases; optimal on small Squares and 3×3×3 scrambles; Square God's numbers | reproduction | Shree |
| Reduction | `m2_reduction` | centers, then the 3×3×3 by Kociemba's two-phase, then wings | reproduction | Sunaina |
| Demaine | `m3_demaine` | Demaine et al.'s parallel cluster algorithm (3-cycle batching on the cube) | reproduction | Kashvi |
| CayleyPy | `m4_cayleypy` | per-size residual MLP distance + beam search | reproduction | Shaurya |
| OneNet | `m5a_tokens` | one cluster-token transformer for every size | **new** | Sharanya |
| NetGain | `m5c_schedule` | net-gain scheduling of bulk commutators | **new** | Gaurav |
| KMC-Repro | `m6_kmcoders` | KMCoders' Santa 2023 pipeline rebuilt from their write-up | reproduction | Gaurav |
| SymPort | `m7_portfolio` | symmetry portfolio around a deterministic solver (main method) | **new** | Gaurav |
| KMC-published | `santa_kmcoders` | KMCoders' published final submission, replayed and re-verified | baseline | — |
| KMC-one run | `kmcoders` | one run of KMCoders' Rust program | baseline | — |
| dwalton76 | `dwalton76` | dwalton76's open NxNxN reduction solver | baseline | — |

`m5b_stages` (learned search inside reduction stages) is an earlier method that is not in the final paper; its code and
results are kept for reference. The engine, beam search and harness (`rubiks/engine`, `rubiks/search`, `rubiks/bench`) are by
Gaurav.

## Install

```bash
python -m venv .venv && source .venv/bin/activate
pip install torch                 # CPU or CUDA build
pip install -e ".[dev]"
pytest -q -m "not slow"           # unit tests, a few minutes
```

On Python 3.12+ the `kociemba` package may fail to build under the newest setuptools; if so, run
`pip install "setuptools<70" cffi future && pip install --no-build-isolation kociemba` first.

## Solve something

```python
import numpy as np
from rubiks.engine import cube, square, random_state, to_notation
from rubiks.solvers import get_solver, Budget, load_all

load_all()
P = cube(6)                                            # or square(N)
state = random_state(P, np.random.default_rng(0))
r = get_solver("m5c_schedule", P, Budget(wall_time_s=120)).solve(state)
print(len(r.moves), P.is_solved(P.apply(state, r.moves)), to_notation(r.moves[:10], P))
```

Benchmark through the harness (it re-applies every solution and decides "solved" itself):

```bash
python -m rubiks.bench make    --puzzle square --N 3-20 --depth random      # data/square/N*/random.jsonl
python -m rubiks.bench run     --solver m5c_schedule --puzzle square --N 3-12 --dataset random
python -m rubiks.bench summary results/m5c_schedule/square_random.jsonl
python -m rubiks.bench make    --puzzle cube --N 4-10 --depth santa         # Santa 2023 cubes (downloaded on first use)
```

## Reproduce the paper

```bash
python paper/scripts/make_tables.py        # every number, table and figure, from docs/results/
cd paper && pdflatex main && bibtex main && pdflatex main && pdflatex main
```

All result files are in `docs/results/` (one JSONL row per instance, with seed, hardware and git commit). The experiment
scripts are in `experiments/` (`m7_santa.py` is the SymPort campaign, `m7_square.py` the Square portfolio, `kmc_one_run.py` the
one-run baseline, `e1`–`e8` the random-state experiments; see `experiments/README.md`). `m7_seed_control.py` (symmetries against
random seeds at equal compute) is written but not yet run.

## External programs (needed only for the Santa baselines and SymPort on cubes)

| Name | What | Setup |
|---|---|---|
| `kmcoders` | KMCoders' Rust solver ([wata-orz/santa2023_permutation_puzzle](https://github.com/wata-orz/santa2023_permutation_puzzle)) | clone it, apply `rubiks/solvers/external/kmcoders_env.patch` (seed and stage-2 length from environment variables; defaults unchanged), `cargo build --release` in `solution/`, set `KMCODERS_DIR` |
| `nxopt` | [Rokicki's optimal 3×3×3 solver](https://github.com/rokicki/cube20src) (GPL-3), quarter-turn build, for SymPort's odd-N 3×3×3 stage | `ctangle nxopt.w; ctangle cubepos.w`, build with `-DQUARTER -DEO1 -DEP3`, set `NXOPT` (and `NXOPT_DIR` for its 1.42 GB table, built on first run) |
| `dwalton76` | [dwalton76's NxNxN solver](https://github.com/dwalton76/rubiks-cube-NxNxN-solver) | build it, set `DWALTON76_DIR` (lookup tables about 8 GB for N ≤ 7) |

KMCoders' repository has no licence file, so this repository contains only our wrapper and the two-line patch, never their
code. The Santa 2023 puzzle files are downloaded on first use into `data/santa2023/` and are not redistributed (Kaggle terms).

## Checkpoints

Trained models are in `checkpoints/` (see `checkpoints/README.md`): CayleyPy's per-size Square networks (`m4/`; the
GPU-trained `square8.large.pt` is the default at N = 8, and `cube3.large.pt` is a 3×3×3 model not used in the paper), OneNet (`m5a/square.large.pt` is the model in the paper's tables),
and the earlier `m5b` models. IDA\*-PDB's pattern databases (`checkpoints/m1/`, about 170 MB per metric) are not included; they
are rebuilt automatically on first use. GPU training ran on a free Colab T4 with
[`notebooks/train_gpu_colab.ipynb`](notebooks/train_gpu_colab.ipynb).

## Layout

```
rubiks/
  engine/      puzzle geometry and moves, canonical form and metrics, clusters with N-invariant signatures,
               projections (exact BFS tables), solvability checker, random states
  search/      shared beam search (3-bit packing, GPU / host / disk tiers, macro actions), 3-cycle and commutator generation
  bench/       datasets, harness (re-verifies every solution), Santa 2023 adapter, CLI
  solvers/     solver interface and registry; one package per method; external/ wrappers for the baselines
  analysis/    the counting lower bound
tests/         engine, checker, beam search, bound, harness, Santa adapter, KMCoders input, every method
experiments/   experiment scripts (SymPort campaign, baselines, E1–E8)
paper/         LaTeX source, generated tables and figures, scripts that build them
docs/          results (docs/results), paper PDF and Overleaf zip, slides, technical basis, architecture notes
demo/          local demo web page and terminal fallback
checkpoints/   trained models
notebooks/     Colab notebook for GPU training
```

More: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) (engine design), [`docs/technical_basis.pdf`](docs/technical_basis.pdf)
(original specification), [`CONTRIBUTING.md`](CONTRIBUTING.md).
